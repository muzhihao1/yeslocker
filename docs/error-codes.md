# 耶氏台球杆存取系统 - 错误码定义

## 错误响应格式

所有API错误响应遵循统一格式：

```json
{
  "errno": 601,
  "errmsg": "用户不存在"
}
```

## 通用错误码 (400-599)

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| 401 | 请先登录 | 跳转到登录页面 |
| 402 | 参数错误 | 检查请求参数 |
| 403 | 参数值错误 | 检查参数值是否合法 |
| 404 | 资源不存在 | 检查请求的资源ID |
| 501 | 请登录 | 跳转到登录页面 |
| 502 | 系统内部错误 | 稍后重试或联系管理员 |
| 503 | 业务不支持 | 功能暂未开放 |
| 504 | 操作频繁 | 稍后再试 |

## 储物柜业务错误码 (600-699)

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| 601 | 用户不存在 | 检查用户信息 |
| 602 | 储物柜不可用 | 选择其他储物柜 |
| 603 | 凭证无效或已过期 | 检查凭证码是否正确 |
| 604 | 您已有正在使用的储物柜 | 先取回现有物品 |
| 605 | 操作记录不存在 | 检查操作ID |
| 606 | 请先完成身份验证 | 跳转到身份验证页面 |
| 607 | 超过最大存储数量限制 | 先取回部分物品 |
| 608 | 今日操作次数已达上限 | 明天再试 |
| 609 | 储物柜已被占用 | 选择其他储物柜 |
| 610 | 凭证已使用 | 凭证只能使用一次 |
| 611 | 非本人凭证 | 使用自己的凭证 |
| 612 | 储物柜维护中 | 选择其他储物柜 |
| 613 | 身份信息不完整 | 补充身份信息 |
| 614 | 手机号格式错误 | 输入正确的手机号 |
| 615 | 身份证号格式错误 | 输入正确的身份证号 |

## 微信相关错误码 (700-799)

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| 701 | 微信登录失败 | 重新授权登录 |
| 702 | 获取用户信息失败 | 重新授权 |
| 703 | 微信code无效 | 重新获取code |
| 704 | 微信session过期 | 重新登录 |

## 权限相关错误码 (800-899)

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| 801 | 无操作权限 | 联系管理员 |
| 802 | 账号已被禁用 | 联系管理员 |
| 803 | Token无效 | 重新登录 |
| 804 | Token已过期 | 重新登录 |

## 前端错误处理示例

```javascript
// utils/request.js
function handleError(error) {
  const { errno, errmsg } = error
  
  switch (errno) {
    case 401:
    case 501:
    case 803:
    case 804:
      // 跳转登录
      uni.redirectTo({
        url: '/pages/user/profile'
      })
      break
      
    case 604:
      // 已有活跃存储，跳转到首页查看
      uni.showModal({
        title: '提示',
        content: errmsg,
        confirmText: '查看',
        success: (res) => {
          if (res.confirm) {
            uni.switchTab({
              url: '/pages/home/index'
            })
          }
        }
      })
      break
      
    case 606:
      // 需要身份验证
      uni.navigateTo({
        url: '/pages/storage/verify'
      })
      break
      
    default:
      // 默认提示
      uni.showToast({
        title: errmsg || '操作失败',
        icon: 'none',
        duration: 2000
      })
  }
}
```

## 错误码使用规范

1. **前端处理**
   - 根据错误码进行相应的页面跳转或提示
   - 401/501/803/804 等认证错误应跳转登录
   - 业务错误应给出明确的操作指引

2. **错误提示**
   - 使用 uni.showToast 显示简单错误
   - 使用 uni.showModal 显示需要用户确认的错误
   - 重要错误记录到日志系统

3. **重试机制**
   - 502 系统错误可以自动重试
   - 504 操作频繁需要延时重试
   - 网络错误应提示用户检查网络

4. **错误上报**
   - 收集关键错误信息
   - 上报到监控系统
   - 便于问题追踪和优化
