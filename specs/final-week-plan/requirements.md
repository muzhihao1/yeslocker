# YesLocker 最后一周开发需求文档

## 1. 项目背景与目标

### 1.1 当前状态
- **后端API**: 100% 完成，基于Litemall框架的Spring Boot应用
- **前端小程序**: 95% 完成，基于UniApp开发
- **管理后台**: 80% 完成，基于Vue.js + Element-UI

### 1.2 本周目标
完成剩余的5%前端功能和20%管理后台功能，实现系统完整闭环，准备正式上线。

## 2. 功能需求详细说明

### 2.1 前端功能需求（Terminal A负责）

#### 2.1.1 储物柜选择页面API对接
**需求描述**: 将现有的模拟数据替换为真实API调用

**验收标准**:
- 用户进入储物柜选择页面时，SHALL从API获取可用储物柜列表
- 当API返回数据时，SHALL正确显示储物柜的编号、区域、尺寸和状态
- 当用户选择筛选条件时，SHALL实时调用API获取过滤后的数据
- 当API请求失败时，SHALL显示友好的错误提示

#### 2.1.2 存取杆完整流程实现
**需求描述**: 实现从申请到完成的完整存取流程

**验收标准**:
- 用户点击存杆时，SHALL创建存储申请并获得申请编号
- 系统SHALL生成包含店铺信息的二维码凭证
- 用户点击取杆时，SHALL验证凭证有效性
- 完成操作后，SHALL更新储物柜状态和用户记录

#### 2.1.3 用户身份验证页面优化
**需求描述**: 增强身份验证功能，支持照片上传

**验收标准**:
- 用户SHALL能够上传身份证照片（正反面）
- 系统SHALL对照片进行压缩（不超过2MB）
- 上传过程中SHALL显示进度条
- 上传失败时SHALL支持重试

#### 2.1.4 历史记录页面
**需求描述**: 展示用户的存取记录

**验收标准**:
- 页面SHALL按时间倒序显示所有历史记录
- 每条记录SHALL包含：操作类型、时间、储物柜号、店铺名称
- SHALL支持下拉刷新和上拉加载更多
- 点击记录SHALL展示详细信息

#### 2.1.5 微信授权测试修复
**需求描述**: 解决开发环境下的授权问题

**验收标准**:
- 开发环境SHALL使用Mock数据模拟授权
- Mock数据SHALL包含完整的用户信息
- 生产环境SHALL正确调用微信授权接口

#### 2.1.6 UI响应式适配
**需求描述**: 确保在不同设备上的显示效果

**验收标准**:
- SHALL适配iPhone 6/7/8/X/11/12/13/14系列
- SHALL适配主流Android设备（屏幕密度1x/2x/3x）
- 横屏模式下SHALL正确显示或提示竖屏使用
- 安全区域SHALL正确处理（刘海屏、药丸屏）

### 2.2 后端管理需求（Terminal B负责）

#### 2.2.1 储物柜批量管理功能
**需求描述**: 支持批量修改储物柜状态

**验收标准**:
- 管理员SHALL能够选择多个储物柜
- SHALL支持批量修改状态（可用/占用/维护）
- 批量操作SHALL在事务中执行，保证数据一致性
- 操作完成后SHALL记录操作日志

#### 2.2.2 操作记录查询优化
**需求描述**: 增强操作记录的查询功能

**验收标准**:
- SHALL支持按时间范围查询
- SHALL支持按用户、储物柜、操作类型筛选
- 查询响应时间SHALL小于200ms
- SHALL支持导出Excel格式

#### 2.2.3 用户管理功能增强
**需求描述**: 完善用户管理功能

**验收标准**:
- SHALL显示用户详细信息（包括认证状态、默认店铺）
- SHALL展示用户操作历史
- SHALL支持用户状态管理（正常/黑名单）
- SHALL支持按条件搜索用户

#### 2.2.4 数据统计仪表板
**需求描述**: 实现数据可视化展示

**验收标准**:
- SHALL展示实时储物柜使用率
- SHALL显示日/周/月存取量趋势图
- SHALL展示各店铺对比数据
- 图表SHALL支持交互（缩放、筛选）

#### 2.2.5 权限管理优化
**需求描述**: 细化权限控制

**验收标准**:
- SHALL支持按店铺分配管理权限
- SHALL实现功能级别的权限控制
- 权限变更SHALL实时生效
- SHALL提供权限配置界面

### 2.3 多店铺功能需求

#### 2.3.1 店铺管理
**需求描述**: 实现店铺的增删改查

**验收标准**:
- SHALL支持创建新店铺（名称、地址、联系方式）
- SHALL支持修改店铺信息
- SHALL支持启用/禁用店铺
- 禁用店铺时SHALL检查是否有进行中的操作

#### 2.3.2 用户店铺绑定
**需求描述**: 用户与店铺的关联管理

**验收标准**:
- 注册时用户SHALL选择默认店铺
- 用户SHALL能够切换默认店铺
- 切换店铺时SHALL检查是否有未完成的存储

#### 2.3.3 数据隔离
**需求描述**: 确保店铺间数据隔离

**验收标准**:
- 储物柜列表SHALL按店铺过滤
- 操作记录SHALL包含店铺信息
- 统计数据SHALL支持分店铺查看
- 管理员权限SHALL限制在所属店铺

## 3. 非功能需求

### 3.1 性能需求
- API响应时间: P95 < 200ms
- 页面加载时间: 首屏 < 3s
- 并发用户数: 支持1000+
- 数据库查询: 使用索引优化，避免全表扫描

### 3.2 安全需求
- 所有API调用必须进行身份验证
- 敏感数据（如手机号）必须加密存储
- 文件上传必须进行类型和大小限制
- SQL查询必须使用参数化防止注入

### 3.3 可用性需求
- 系统可用性 > 99.9%
- 支持优雅重启，不影响用户操作
- 实现熔断机制，防止雪崩
- 关键操作支持幂等性

### 3.4 兼容性需求
- 微信小程序基础库 > 2.10.0
- iOS > 10.0
- Android > 5.0
- Chrome/Safari/Firefox最新版本
